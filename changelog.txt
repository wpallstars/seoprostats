== Changelog ==

Every change to SEO Pro Stats. readme.txt lists the latest version in short.

= Unreleased =
* New: Settings → Import brings another statistics plugin's history across, starting with Burst Statistics (read from version 3.7.2). Its data is found from its tables whether the plugin is active, inactive or deleted, cached for ten minutes. A dry run lists the days, the days skipped and why, the plugin's own counts, the rows per report, days shared with another plugin not imported yet (choose which fills them; the other fills only the days left) and the settings it would fill in, writing nothing. The import is whole days in daily (schema v15 adds daily.import_id): only days before SEO Pro Stats's own first day and not filled by another import, so a second run adds nothing, and the daily summaries never touch imported rows. It runs from WP-Cron and the tab's polling in 20-second budgets under a lock (WP-CLI to the end), each day in one transaction. Only counts are read: no IP addresses, visitor IDs or user agents; a bounce is a visit of one pageview, as SEO Pro Stats counts it. The finished import shows the plugin's own counts beside the imported ones, a link to the Overview for those days and the next steps, adds a note on the timeline, and can be undone; settings with an equivalent (Do Not Track, excluded roles and IP addresses) are filled in only where still at their default. Once the plugin is inactive, Remove leftover data deletes exactly the tables, options, transients, cron hooks, user meta and files it left on this site, after confirmation, and notes it on the timeline. REST GET /migrate, POST /migrate/{source} (dry_run, prefer, from, to), POST /migrate/{source}/cleanup; DELETE /imports/{id} undoes these imports too; wp seoprostats migrate list|run|imports|undo|cleanup; abilities seoprostats/migrate and seoprostats/migrate-import (removing leftovers is for people only); the seoprostats_migrate_sources filter adds adapters.
* New: Search → Rankings → Days (tab=days): the chart's points as a table, newest first, with clicks, impressions, CTR and position for each day, or each week or month when the chart shows those (a week labelled by its first day). It works for Google, Bing and Combined and for one page or one query, and pages through long periods with Newer and Older; the comparison stays on the totals. REST search?kind=days (each row with from and to, the days it covers), wp seoprostats search days (with --offset) and the seoprostats/search ability with kind days (which now takes offset). Rows come from the same points as the chart, so no extra query.
* New: Search → Rankings → Appearance (tab=appearance): Google Search Console clicks, impressions, CTR and position by search appearance (video, product snippets, review snippets, forums and any other type Google returns), for the whole site and Google only, against the previous period. One search can show several appearances, so the rows are counted by page and do not add up to the site's totals. After search days are imported, one request finds the appearance types in them and one more per type reads its days, carrying on in the next run when time runs out; each run's appearances are one import that can be undone, and importing days again replaces them, removing types Google no longer returns. Schema v14 adds gsc_appearance (primary key engine, day, appearance_id), kept as long as search pages and queries. REST search?kind=appearance, wp seoprostats search appearance and the seoprostats/search ability with kind appearance; demo data has made-up appearance days, each type with its own CTR and position.
* New: Search → Combined, beside Google and Bing once both have data: Rankings, Opportunities and Content add up every search engine with data. Clicks, impressions and position × impressions are summed, so CTR and position are over all of them, and a query or page shown on more than one engine is one row. The period ends at the earliest of the engines' newest days, in whole weeks with Bing (a page's or query's chart by week), with no countries or devices; each engine counts its own days. REST and abilities engine=all, WP-CLI --engine=all on search, opportunities and content; while only one engine has data, all answers as that one. The other Search reports show Google while Combined is chosen; shared reports keep one engine per section.
* New: separate daily subscription renewal counts and currency amounts from WooCommerce Subscriptions, FluentCart and ThriveCart, without fabricated visits or Purchase completions. GET /goals and doctor report 400-day totals; serialized private payment hashes deduplicate callbacks and fail closed at receipt capacity. EDD Recurring remains unverified.
* New (GitHub builds): admin screens no longer wait for update servers. When WordPress's stored core, plugin or theme update check is 12 hours old, the next admin screen opened ran it, waiting while WordPress and every plugin's own updater asked their servers. The shared updater (version 1.4.0, from the starter plugin) schedules that check as core's own cron event instead, and WP-Cron starts it in the background as the screen finishes. The Plugins, Themes and Updates screens still check as before, as do the twice-daily checks, the checks after updating and automatic updates; while WP-Cron is not running, or when a check cannot be scheduled, checks stay on admin screens. The wpallstars_github_updater_checks_in_cron filter turns this off.
* Developers: the shop-test and demo-site notes in DEVELOPMENT.md, the shop-test release step in RELEASING.md and the shop-test fixture line in .distignore sit in spst-own blocks, which scripts/sync-core.sh keeps, so a core sync no longer deletes them.
* Changed: Settings → Shared reports can be filled in. Agency branding is a switch with the agency's name, website, byline and a logo picked from the Media Library; Report colours picks the accent from the site's theme, Site Editor or Customizer colours (or any other) and whether reports open light, dark or following the reader's device; the credit reads "Statistics logged by SEO Pro Stats for WordPress". Share sits after the period controls on every tab and also shows with demo data, where it cannot be pressed.
* Changed: every tab can be a shared report section: Overview, Search (once for each engine, with Rankings, Opportunities, Audit and Content; never the Plan or Experiments), Goals, Funnels, Properties, Clicks and Changes, each once. Reports with Search or Changes can lock pages only. The share editor groups its fields, orders and removes sections, offers only sections not yet added, says why a field cannot be used, previews Media Library logos and starts from the Settings defaults; reports can be edited from the list. The private link shows in a notice with Copy and Open. The reader's report has a header with the logo, title and section, light or dark and print buttons, readable dark fields, and no owner hints or names of who made changes; printing is light whatever the screen, fits the charts to the page and lists the period's changes by date.
* New: Search → Plan (report=plan), the decision queue: one ranked list of search work made from the opportunities (ctr: rewrite a title and description; missing: answer a search the page lacks; striking: improve a page at positions 4–20; decay: find why a page lost clicks, then update it). Each item has its page and query, why it is listed, what to do, its figures and its score, potential clicks per 28 days × value × confidence ÷ effort, with every part: value is the page's conversion rate of visits from search for a goal (smoothed toward the site's, chosen with goal=) against the site's, from 1 to 5; confidence is the kind's own, less below 1,000 impressions per 28 days; effort is the kind's unless someone sets another (1–5). Accept, Done (starts an experiment on the page with the kind's measure; the item then shows its result), Dismiss (hidden for 90 days) or Restore an item, and set its effort or a note; status= in the address keeps the state shown. New items on a page with a running experiment are left out, so one change is measured at a time. Items are worked out from the cached Opportunities and Content reports when the list is read; schema v9 adds the queue table (unique ikey; status and updated) for those someone acted on. REST routes queue and queue/{key}, wp seoprostats queue (list, accept, done, dismiss, restore, effort, note) and, on WordPress 6.9 and later, the abilities seoprostats/queue and seoprostats/queue-update; demo data has one item accepted and one done.
* Changed: the statistics screen has the settings screen's header: name, version, feature search (for administrators) and the Source code, Support and Buy me a coffee buttons. Its section tabs (Overview, Search, Goals, Funnels, Properties, Clicks, Changes) look like the settings tabs, full width under the header, with the live count, the Live/Demo switch, the period and the comparison on the bar's right (under the tabs on a phone).
* Fixed: a chart marker's dot sits in the middle of its circle.
* Changed: settings tabs (Shared reports, Tracking, Privacy, Data and Connections) switch at once, without loading the page again; the address follows the tab, so Back, reload and bookmarks still work. Read Me still opens as its own page.
* Fixed: GitHub updates refresh their release information when WordPress's update cache is cleared (shared updater 1.3.1, from the starter plugin).
* New: Search → Experiments (report=experiments): record a change and what it should do (clicks, impressions, CTR, position, visits from search or conversions of a goal, up or down, by at least a threshold) before the result is known, from a row in Changes or with a start and up to 50 pages. Equal windows of 7 to 84 days before and after the change (the change day left out; Bing's weekly page rows from the week after) set its pages against up to 200 unchanged pages, with the effect, the 10th to 90th percentile of the unchanged pages' own effects, whether there was enough data, and the search engine updates, site-wide changes and other changes to its pages in the span. Once the data reaches the review day it suggests keep, revise, undo or inconclusive; a person or agent decides with a note, and the decision keeps the measurement it was made on. Each start is a change of kind experiment (group note) on the timeline. Schema v8 adds the experiments table (keys status and review, path_id, start); measurements read gsc_pages by its primary key, the daily search landings and the change log by ts, and are cached like the reports. REST routes experiments and experiments/{id}, wp seoprostats experiments (list, add, show, decide, cancel, note, delete) and, on WordPress 6.9 and later, the abilities seoprostats/experiments and seoprostats/experiment-record; demo data has one experiment of each result.
* New: private shared reports for Overview, Goals and Clicks, with ordered saved views, password, expiry, revocation and link renewal, locked filters and period limits enforced on the server. Standalone untracked read-only page, local site and agency branding, contrast-checked accents, light/dark/system appearance and print styles. Administrators manage shares by REST, WP-CLI or the Shared reports screen; only token hashes and password hashes are stored.
* New: query coverage. Each page's Search Console queries are checked against its own words: covered by the title (post or SEO title), a heading, the text (with excerpt, image alt text and SEO description), partly or not at all, with the words missing and whether the query is a question. Search → Opportunities gains Missing from the page (kind=missing): top-20 queries with enough impressions that their page does not cover, most impressions first, reading the 50 pages with most impressions among them. The post editor shows a Search queries panel (block editor sidebar, or a meta box in the classic editor) with the share of impressions covered, the focus keywords, the queries not covered and the questions, re-checked as people write. Focus keywords come from Rank Math, Yoast SEO, SEOPress or All in One SEO (filter seoprostats_focus_keywords for others); without one the rest works the same; filter seoprostats_coverage_text adds a page builder's text. REST route coverage (page or post), wp seoprostats coverage and, on WordPress 6.9 and later, the ability seoprostats/coverage; demo pages have text to check against. Reads one page's queries by the path_day key; nothing runs on visitor pages.
* New: Search → Content, beside Opportunities (report=content): per page, Google's search clicks, position and CTR with the visits from organic search that started on it (any engine), their bounce rate, views and time, and how many reached a goal (the first, or one chosen), against the previous period. Sort by clicks, visits or conversions (sort=, goal= in the address); choose a page to open it in Rankings. Reads gsc_pages by its keys, a new daily summary of search landings by entry page, and the goal's hits by their index; days summarised before the update are filled in, newest first, by the background rollup, and the report says so until they are. REST route content, wp seoprostats content and, on WordPress 6.9 and later, the ability seoprostats/content. Demo visits from search engines now land on the pages its search data sends clicks to.
* Changed: choosing a marker under a chart (Overview or Search) shows its changes in a window over the report, closed with Close or Escape, with Open in Changes for the same days (and page); the Changes section keeps its page in the address. Markers whose pills would touch, as on a phone, merge into one, so each can be chosen.
* Changed: Search's Page and Query boxes each have an × that clears the box and applies at once.
* Fixed: space between the Search Console notice and the cards under it, and between Search's cards; a one-day period reads as one day; windows fill a phone's width.
* New: Search → Opportunities, beside Rankings (its own address, report=opportunities): where search effort pays. Striking distance lists a page's queries at positions 4–20 with the clicks they could gain in the top three; Low CTR lists top-10 queries chosen much less often than the site's own CTR at that position (title and description work); Losing clicks lists pages with at least a fifth fewer clicks than the earlier period, each with its likely cause (ranks lower, fewer searches, lower CTR or no longer shown), the queries that lost most and the changes made to the page, with search engine updates in the two periods. Expected CTR is measured from the site's own search data, with a cautious default where it has too few impressions. Choose a row to open it in Rankings. Reads at most the newest 91 days of the period, by the search tables' keys. REST route opportunities, wp seoprostats opportunities and, on WordPress 6.9 and later, the ability seoprostats/opportunities; demo data shows an example of each.
* Changed: the address keeps each section's choices, so a bookmark, a reload, a copied address or the back button brings back the same view: the Clicks table and page, the Properties property and event, the Search table, chart, page and query, the Changes page and group, and the tab of each Overview card. Changes uses the address's page before the report's page filter; Any page clears both. Changing section keeps the period, comparison and filters and leaves the other section's choices behind; unknown values open the defaults.
* Changed: Settings → Connections walks through the Search Console setup in six steps, each linking to the Google page it needs (new project, Search Console API, service accounts, keys, Search Console users), with what to choose on each and what to do if an organisation policy blocks keys. The README has the same steps.
* New: a Search section (Rankings), with its tab and menu item: Google Search Console's clicks, impressions, CTR and average position for the period against the previous one, a chart of the one you pick with the changes lane, and the queries, pages, countries and devices, sorted by clicks. Choose a page for its queries or a query for its pages. The period ends at the newest final day (about three days ago) and the comparison has as many days, so days not imported yet never look like a drop. Before Search Console is connected it links to Settings → Connections. REST route search, wp seoprostats search and, on WordPress 6.9 and later, the ability seoprostats/search; demo data has made-up search data too. Reads only the imported search tables, by their keys; never on visitors' pages.
* New: Pages in the Clicks report lists clicks, dead-click rates, links, forms and visits per page. Choose a page to narrow the section, choose again to clear it, and use View page or Edit (only with permission). REST clicks kind=pages and page_info; wp seoprostats clicks pages and page details.
* New: refunds from WooCommerce, Easy Digital Downloads 3, FluentCart and ThriveCart join the original purchase visit, once per refund. Purchase goal and property revenue subtract them per currency without increasing purchase completions; refunds never invent visits after retention.
* New: statistics collection without cookies: a collector that runs without loading WordPress (or the REST route on the WordPress.org build), daily-salted visitor hashes, and a processor that turns hits into visits, pageviews, events and properties every minute.
* New: reports for scripts and AI agents: the REST API (stats, timeseries, breakdown, realtime, markers) and wp seoprostats commands, with ranges, comparisons and filters.
* New: the SEO Pro Stats menu (under Dashboard) and its Overview: headline metrics with a chart against the previous period, Sources, Pages, Locations and Devices, filters by clicking any row, live visitors, and a view kept in the address so it can be bookmarked. Follows the admin colour scheme; every chart has a table for screen readers.
* Changed: the settings screen is SEO Pro Stats → Settings, the last item in the plugin's own menu, and no longer also under WordPress's Settings menu. Old links to it still work.
* Changed: when SEO Pro Stack organises the admin menu, the SEO Pro Stats menu stays at the top under Dashboard, with the other site statistics, instead of under Administrators.
* New: a Dashboard widget with today so far against yesterday at the same time and the last 7 days' visitors.
* New: the tracker, printed inline on front-end pages (about 2.5 KB compressed, no cookies or browser storage): pageviews with single-page app navigation, visible time and scroll depth, outbound links, file downloads, and events from seoprostats('Name', {...}) or data-sps-event attributes. Editors, feeds, previews and the customizer are not counted; filters add excluded paths and Do Not Track / Global Privacy Control.
* New: demo data: a Demo data switch on the Overview shows a little over a year of made-up visits, kept in tables of their own, apart from your live statistics; the Dashboard widget follows it. wp seoprostats demo, and data=demo on the reports.
* New: Goals, Funnels and Properties sections, with tabs and menu items: conversions, conversion rate and revenue per currency for each goal; visits and drop-off at each funnel step in order within one visit; property keys and values with revenue. Administrators add, change and delete goals and funnels; demo data has its own examples. REST routes goals, funnels and properties, and wp seoprostats goals, funnels and properties.
* New: choosing a row that already filters the reports removes the filter.
* New: click and form autocapture, and a Clicks section with its tab and menu item: clicked elements, dead clicks, link destinations, file links and forms sent, on the site or one page. Never what anyone types; emails and long numbers in labels are hidden, and data-sps-mask hides an element's text. Affiliate links (Settings → Tracking paths, or rel="sponsored") send an Affiliate link event. Clicks are kept 3 months (Settings → Data). REST route clicks and wp seoprostats clicks; demo data has clicks too.
* New: pages not found, site search, content and logged-in visits. The Pages card has a Not found tab (404s by address, to find broken links); a Site search card shows what people searched for and the searches that found nothing; a Content card shows views by author, category and post type; the Devices card has a Logged in tab. Search words are kept with emails and long numbers hidden, and Settings → Tracking can leave them out. All are filters and breakdowns in the REST API and WP-CLI (not_found, search, no_results, author, category, post_type, login), and demo data has them too. Visitor pages still run no queries: the page says which post it shows, and the minute job looks up its author and category.
* New: purchases. Paid orders from WooCommerce, Easy Digital Downloads and FluentCart become a Purchase event with the order's total in its currency, on the visit that placed it, once per order; ThriveCart orders too, through its webhook and the page's ID on ThriveCart links. No order numbers or customer details are kept. Settings → Tracking → Record purchases; seoprostats_purchase filter; wp seoprostats doctor lists the shops recorded.
* New: a change log of what changed on the site, when and on which page: posts and pages published, unpublished, moved, retitled and edited (words added and removed, internal links, external sites linked); SEO titles, descriptions, robots and canonicals from Yoast SEO, Rank Math, SEOPress and The SEO Framework; WooCommerce prices, sales, stock and coupons, and Easy Digital Downloads prices; plugins, themes and WordPress installed, updated, activated or switched; search engine visibility, permalinks, site address and front page settings. REST routes markers (now filled, for the charts) and changes, and wp seoprostats changes, with page and kind filters; seoprostats_record_change filter; demo data has changes too. Recorded when the change is saved, never on visitors' pages; the tables update by themselves.
* New: a Changes section, with its tab and menu item, and a markers lane under the Overview's chart: what changed in the period, coloured by group (content, SEO, products, site, notes), for the site or one page; markers are buttons that list their changes and open Changes. Administrators add and delete notes for what the log cannot see, such as a newsletter sent. REST routes POST /annotations and DELETE /annotations/{id}, wp seoprostats annotate, and on WordPress 6.9 and later the abilities seoprostats/markers and seoprostats/annotate; demo data has notes too.
* New: search engine updates on the timeline, off until switched on under Settings → Data: Google's ranking updates with their type (core, spam, reviews and others) and its crawling, indexing and serving incidents, fetched from its Search Status Dashboard once a day by the daily job (never on visitors' pages; nothing about the site is sent), with past ones added the first time, and posts naming an update from other RSS, Atom or JSON feeds you add. A bar in the markers lane shows each rollout, including ones that began before the period; Changes has a Search engines group and links each update to its source. Kind search_update, group search; wp seoprostats search-updates fetch and status; wp seoprostats doctor shows failed sources, which are asked again the next day. Demo data has made-up updates too.
* New: Google Search Console, off until connected under the new Settings → Connections tab with a Google Cloud service account's JSON key, stored encrypted (libsodium; SEOPROSTATS_ENCRYPTION_KEY in wp-config.php, else the site's security keys) and never shown again. Clicks, impressions and average position by page, query, page and query, and device and country are imported for each final day (never preliminary figures), with the 16 months Search Console keeps imported on connecting, newest first, by WP-Cron within a 20-second budget per run; never on visitors' pages. Each import is listed and can be undone; Import now fetches what is ready. Search data by page and query is kept 25 months (Settings → Data); daily totals are kept. REST routes connections and imports; wp seoprostats connect, disconnect and search-console (status, import, imports, undo, reimport); wp seoprostats doctor shows its state; seoprostats_search_import_limits filter. The tables update by themselves.
